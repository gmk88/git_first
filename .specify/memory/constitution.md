# git_first AI 编码宪法

版本：1.0.0｜状态：生效｜范围：本仓库全部 AI 辅助编码活动

本文件是 Agent 的执行约束，不是风格建议。每次提出方案、制定计划、修改代码和验收前，
必须重新读取本文件；冲突时以本文件的 NON-NEGOTIABLE 条款为准。

## 0. 术语与边界

- **必须 / 禁止 / NON-NEGOTIABLE**：不可违背；违反即阻断交付。
- **应当**：默认执行；不执行必须记录具体理由和替代方案。
- **可以**：可选项，不代表授权扩大范围。

本文件不是需求说明、架构方案或任务清单，也不授予新增功能的权限。未获批准的需求、
架构和依赖变化一律不做。禁止使用"最佳实践""高质量""整洁代码"等模糊表述作为验收
依据；需要执行的外部标准必须转写为本文中的具体规则。

## 1. 行为边界【NON-NEGOTIABLE】

- **只实现已批准 spec/tasks 中的行为，只修改必需文件。**禁止顺手重构、全仓格式化、
  无关重命名、升级依赖、删除文件或改变公开 API。理由：限制爆炸半径，防止误差跨阶段累积。
- **沿用仓库现有分层、依赖方向和数据流。**禁止自动引入
  router/controller/service/repository 等额外分层，禁止为单一用途预设
  interface、factory、adapter 或通用框架。理由：避免 AI 把默认架构偏好强加给项目。
- **需求冲突、信息不足或改动越界时，停止相关修改。**必须提出具体问题和最小可选方案，
  不得自行补全需求。理由：自行解释模糊要求会产生不可控输出。
- **未经明确许可，禁止 commit、push、reset、rebase，禁止外发代码或数据，
  禁止读取后输出密钥，禁止破坏性文件或数据库操作。**理由：不可逆动作必须由人授权。

## 2. 先读后写与强制复用【NON-NEGOTIABLE】

- **修改前必须检索并阅读目标模块、调用方、相关测试、配置及相邻实现，并在变更记录中
  写明检索位置和复用结论。**理由：AI 天生倾向"写"而非"读"，必须先建立真实上下文。
- **新增能力前必须列出可复用的现有模块。**不能复用时，记录具体接口或行为差异；
  禁止复制现有函数后改名、小改。理由：重复实现会制造分叉逻辑和维护成本。
- **项目实际架构只以当前代码和已批准 design 为准。**禁止根据想象补充目录、模块或
  调用关系。理由：防止虚构结构污染实现。

## 3. 可验证代码约束【NON-NEGOTIABLE】

- **单个函数不超过 50 行（不含空行和注释）；超出必须按单一职责拆分。**理由：限制
  认知负担，使审查和测试可定位。
- **禁止空 catch、只记录日志后静默继续、返回无说明的 null 掩盖失败。**错误必须返回、
  抛出或转换为明确状态。理由：失败不可消失，误差不得进入后续步骤。
- **所有外部输入必须在系统边界校验；数据库查询必须参数化；鉴权必须在服务端执行；
  对外资源标识必须使用 UUID 或等强度不可枚举标识。**理由：分别阻断非法输入、注入、
  越权和枚举攻击。
- **禁止硬编码密钥、动态执行不可信字符串、关闭传输安全校验、新增未批准依赖。**
  理由：这些行为会直接扩大供应链和运行时风险。
- **保持现有公开契约和数据兼容。**不兼容变更必须先提供迁移与回滚方案。理由：局部
  修改不得破坏既有调用方。

## 4. 测试与证据【NON-NEGOTIABLE】

- **每个新增或修改行为至少对应一个自动化测试，或一条可复现的验收步骤；缺陷修复必须
  覆盖原失败路径。**理由：没有可执行证据的"完成"不可验收。
- **禁止删除、跳过或放宽既有测试与断言；禁止用 mock 掩盖真实集成故障。**理由：不得
  降低验收标准，测试必须反映真实行为。
- **交付前必须运行与改动相关的测试、lint 和类型检查，并记录命令及结果。**未运行的
  项目必须标记"未验证"，禁止声称通过。理由：结论必须可追溯、可复核。

## 5. 阻断式 Quality Gates

| Gate | 通过条件 |
|------|----------|
| G0 范围 | spec/tasks 已批准；每个改动文件可映射到任务 |
| G1 复用 | 已记录检索位置、候选模块及复用或不复用理由 |
| G2 实现 | diff 未越界；函数长度、禁止项、依赖和契约检查通过 |
| G3 验证 | 相关测试、lint、类型检查通过；spec 场景全部验收 |
| G4 交付 | 列出改动文件、验证证据、未验证项和残余风险 |

**任一 Gate 未通过，状态只能是进行中或阻塞，禁止标记完成。**每个阶段结束后立即
纠偏，不得把未解决误差带入下一阶段。

## 6. 修订与 SemVer

- NON-NEGOTIABLE 条款只能通过修订本文件变更；任何对话中的"临时忽略"均无效。
- MAJOR：删除或放宽约束；MINOR：新增兼容约束；PATCH：澄清文字且不改变语义。
- 每次修订记录版本、日期、原因和影响范围；优先删除重复或冲突条款，不以增加长度
  代替严格度。正文控制在 500–2000 字。
